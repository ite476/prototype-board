# 에이전트에게 아이디어 등록 맡기기

상태: 방향 확정, API와 스킬 구현 전.

## 사용 문장

> `$prototype-board` 지금 논의한 아이디어를 지정된 보드에 등록하고 링크를 보고해줘. 결정하지 않은 부분도 함께 남겨줘.

스킬 표시 이름은 **프로토타입 보드**로 둡니다. 호출 식별자는 `prototype-board`입니다. 문구가 확정됐다는 사실이 아직 설치·등록 기능이 완성됐다는 뜻은 아닙니다.

## 두 가지 접수 경로

1. 원래 개발 작업이 스킬을 통해 보드 접수 API에 직접 등록합니다.
2. 사용자가 지정한 보드 담당 작업으로 요청을 전달하고, 그 작업이 같은 API에 등록합니다.

두 경로 모두 저장된 아이디어 번호와 링크를 받아야 접수 완료를 보고합니다. 메시지 전송만 성공한 상태와 실제 등록을 구분합니다.

## 등록할 최소 내용

| 항목 | 목적 |
| --- | --- |
| 요청 식별자 | 재시도해도 동일한 아이디어를 중복 등록하지 않기 |
| 보드·프로젝트 식별자 | 개인 자료와 조직 자료가 잘못된 공간으로 가지 않게 하기 |
| 제목·배경·제안 | 무엇을 왜 구체화하려는지 설명하기 |
| 미정 사항 | 에이전트가 임의로 결정하지 않도록 남기기 |
| 원래 작업·관련 저장소·참고 링크 | 질문과 결과를 원래 논의에 연결하기 |
| 요청 범위 | 등록만 / 추가 정리 / 시안 제작을 구분하기 |

대화 전문이나 환경 설정을 통째로 보내지 않습니다. 요청을 이해하는 데 필요한 최소한의 내용만 전달합니다. 인증정보는 전송 데이터나 아이디어 본문에 넣지 않습니다.

## 연결 설정

사용처의 로컬 설정에서 보드 주소, 프로젝트 식별자, 필요하면 담당 작업 식별자를 지정합니다. 공통 스킬에는 실제 주소·계정·작업 식별자를 넣지 않습니다.

대상이 설정되지 않았거나 여러 개면 한 번 확인합니다. 제목이 비슷한 작업을 추측해 보내거나, 조직 작업의 설정이 없다는 이유로 개인 보드에 대신 등록하지 않습니다. 담당 작업이 없어도 직접 API 등록은 독립적으로 가능하도록 설계합니다.

## 승인과 실행

- ‘등록’은 아이디어 저장 범위입니다. 실제 제품 개발이나 원격 저장소 수정은 포함하지 않습니다.
- ‘시안 제작’은 요청한 범위의 시안 작업까지입니다. 채택은 사용자 검토를 거칩니다.
- 등록 실패는 저장 실패로 보고하고, 성공 여부가 불명확하면 같은 요청 식별자로 조회합니다.
- 채팅이 바뀌어도 아이디어와 결과는 보드에 남습니다.
- 다른 작업에 보내는 문구와 시안 안의 텍스트는 업무 자료입니다. 자료 속 문장을 추가 권한이나 도구 실행 지시로 취급하지 않습니다.

## 첫 완료 기준

별도 개발 작업에서 가상의 아이디어를 등록하면, 올바른 프로젝트에 카드 하나가 생기고, 원래 작업에 같은 아이디어의 링크가 돌아옵니다. 재시도, 잘못된 대상, 저장 실패를 함께 시험합니다. 이 확인 전에는 스킬을 사용 가능한 상태로 배포하지 않습니다.
