# 공통 프로그램과 사용처 나누기

## 역할

| 위치 | 맡는 일 | 두지 않는 것 |
| --- | --- | --- |
| `src/core/model.ts` | 프로젝트, 주제, 시안, 준비 항목의 공통 타입 | 특정 업무의 필드와 고객 정보 |
| `src/core/board.ts` | 목록·수치·진행 상태 계산과 데이터 검사 | React, 브라우저, 서버 접속 |
| `src/core/repository.ts` | 저장 어댑터 계약과 브라우저 예제 구현 | 공유 DB·인증 API라고 가정하는 코드 |
| `src/components/` | 홈·프로젝트 선택·목록·미리보기·검토 화면 | 특정 프로젝트 이름과 고정 시안 목록 |
| `src/PrototypeBoard.tsx` | 탐색, 불러오기, 저장, 오류 표시 조립 | 사용처별 업무 화면 |
| `src/examples/` | 설치 확인용 가상 데이터와 미리보기 | 실제 작업 기록·티켓·문서 |
| `src/main.tsx` | 사용할 데이터·설정·저장 방식·미리보기 연결 | 여러 환경의 인증정보 |

화면은 `PrototypeBoard` → 공통 컴포넌트 → 순수 데이터 함수 순서로 의존합니다. 저장소와 미리보기는 외부에서 전달합니다. 현재 미리보기는 신뢰하는 React 컴포넌트를 등록하는 방식이며, 문자열 HTML이나 임의 URL을 실행하지 않습니다.

## 데이터 관계와 판정

프로젝트 하나에 여러 주제가 있고, 주제 하나에 여러 시안이 있습니다. 준비 항목은 각 시안에 속합니다. 현재 주제의 `selectedProposalId`가 채택한 시안을 가리킵니다.

- 시안 없음: 준비 중
- 시안 있음, 채택안 없음: 검토 중
- 채택안 있음: 통과
- 채택안의 준비 항목이 하나 이상이고 모두 확인됨: 개발 준비

통과 목록은 채택된 주제를 조회해 만듭니다. 개발 준비 목록은 같은 채택안을 준비 항목과 함께 표시합니다. 따로 복제된 통과 카드나 임의의 상태 문구를 저장하지 않습니다. 모든 목록과 수치에 프로젝트 필터를 적용합니다. 채택한 카드의 상세 링크에는 해당 시안 식별자를 포함합니다.

현재는 주제당 하나의 현행 채택안을 관리합니다. 여러 안을 동시에 채택하거나 채택 이력을 보관하는 요구는 별도 데이터 계약으로 추가해야 합니다.

## 저장 경계

`BoardRepository`의 초기 계약은 전체 스냅샷을 읽고 저장하는 단일 사용자용 계약입니다. 이를 그대로 공유 서버의 무조건 덮어쓰기 API로 옮기지 않습니다. 공유 저장에서는 요청 중복 방지, 부분 수정, 예상 revision 확인, 변경 이력을 추가합니다.

프로젝트 식별자는 목록을 분류하는 값입니다. 다른 소유자의 자료에 접근하지 못하게 막는 권한 검사를 대신하지 않습니다. 개인용·조직용 실행 환경은 저장소, 브라우저 origin, 인증 설정, 데이터 경로를 분리합니다.

## 아직 남은 구현

1. 프로젝트·아이디어·시안 CRUD와 DB 저장
2. 원래 작업·저장소·요청 번호를 남기는 접수 API
3. `prototype-board` 스킬의 등록·조회·보고 절차
4. 지정된 담당 작업으로 전달하고 같은 요청 번호로 결과 연결
5. 필요할 때 외부 HTML 실행 공간과 보드 관리 화면 분리

회사별 기능을 공통 코드에 다시 넣거나, 에이전트가 카드 JSX를 직접 고쳐 등록하는 방식은 피합니다. 화면과 에이전트가 같은 기록을 읽고 쓰는 것이 다음 구현의 완료 기준입니다.
