# 프로토타입 보드

여러 화면 시안을 직접 살펴보고, 채택한 안과 개발 전에 확인할 내용을 모아두는 재사용 가능한 웹 프로그램입니다.

이 저장소에는 공통 기능과 가상의 예제만 둡니다. 실제 업무 자료, 조직별 설정, 인증정보, 실행 중 생성된 기록은 별도 저장 공간에서 관리합니다.

## 현재 할 수 있는 일

- 프로젝트 이름을 눌러 프로젝트를 바꾸기
- 공통 카드에서 주제와 실제 시안의 축소 미리보기 확인하기
- 한 주제의 여러 시안을 바꿔가며 직접 눌러보기
- 시안을 채택하고 통과 목록에서 다시 열기
- 채택을 취소하고 검토 목록으로 되돌리기
- 준비 항목을 확인하고 개발 준비 상태로 이동하기
- 설정, 데이터, 미리보기 컴포넌트, 저장 어댑터를 바꾸어 재사용하기

초기 예제에는 채택한 시안이 없습니다. 통과 목록은 시안 상세 화면에서 채택 버튼을 누르면 채워집니다. 준비 항목이 없는 시안을 자동으로 개발 준비 완료로 처리하지 않습니다.

## 로컬 실행

Node.js 22.18 이상이 필요합니다.

```sh
npm ci
npm run dev
```

기본 주소는 http://127.0.0.1:5188 입니다. 포트가 사용 중이면 임의의 다른 포트로 옮겨가지 않고 실행을 멈춥니다.

```sh
npm test
npm run build
```

정적 배포 결과물은 `dist/`에 생성됩니다. 외부 API·지도·폰트·인증 서비스는 기본 예제의 필수 의존성이 아닙니다.

### Docker로 실행

```sh
docker compose up --build -d
```

`BOARD_WEB_PORT`로 포트를 지정할 수 있습니다. 기본 바인딩은 `127.0.0.1:5188`이며 외부 네트워크에는 열지 않습니다. Docker는 선택 사항이고, 이 초기 버전에는 DB나 Redis가 필요하지 않습니다.

## 저장과 보장 범위

기본 예제의 채택 결과와 준비 항목은 **현재 브라우저의 localStorage**에 저장됩니다. 여러 탭·브라우저·기기 사이의 동시 편집은 보장하지 않습니다. 브라우저 데이터를 지우면 검토 기록도 사라집니다. 저장이 실패하면 오류를 표시하고 마지막 저장 상태를 유지합니다.

아직 포함하지 않은 기능:

- 프로젝트·아이디어·시안 전체 CRUD 및 감사 이력
- 접수 API, DB 기반 영구 저장, 에이전트의 실제 아이디어 등록
- 사용자 인증, 조직별 권한, 동시 수정 충돌 처리
- 외부 HTML을 격리해서 실행하는 기능
- 다른 작업으로의 자동 전달·회신, 실제 제품 개발·배포 자동화

`$프로토타입 보드`를 통한 아이디어 등록은 확정한 확장 방향입니다. 표시 이름은 **프로토타입 보드**, 스킬 식별자는 `prototype-board`로 잡습니다. 접수 API가 구현되기 전에는 등록 기능이 동작한다고 보고하지 않습니다. [접수 기능 설계](docs/agent-intake.md)를 참고하세요.

## 공통 기능 사용하기

`src/main.tsx`가 예제를 조립하는 지점입니다. `src/index.ts`에서 공통 진입점과 데이터 타입을 가져올 수 있습니다.

```tsx
<PrototypeBoard
  config={boardConfig}
  initialData={boardData}
  repository={boardRepository}
  previews={previewRegistry}
/>
```

`src/examples/`는 삭제·교체 가능한 가상 예제입니다. 공통 코드는 예제를 import하지 않습니다. 초기 형태는 소스 수준에서 재사용하는 React 프로그램이며, npm 패키지 배포는 아직 구성하지 않았습니다.

자세한 경계와 후속 작업은 [내부 구성](docs/architecture.md)을 참고하세요.

## 비공개 원본과 사용처

저장소의 기본 관리 방향은 비공개입니다. 공개 라이선스를 선택하거나 npm에 배포하는 절차는 이번 초기 구성에 포함하지 않았습니다.

사용처에서 이 프로그램을 fork하더라도 실제 작업 자료와 비밀 설정은 별도 보관합니다. private fork는 완전히 독립된 자료 보관 경계가 아닙니다. 원본 소유자는 같은 fork 연결망의 저장소를 읽을 수 있고, private 원본 삭제는 private fork에도 영향을 줄 수 있습니다. 조직으로의 private fork는 계정 요금제와 관리자 정책도 확인해야 합니다. [GitHub 공식 안내](https://docs.github.com/en/pull-requests/reference/forks)

자료를 원본 소유자와도 분리해야 하는 경우에는 공통 프로그램만 버전별로 가져오는 독립 저장소나 패키지 의존 방식을 검토합니다. Git 저장소의 공개 여부와 실행 중인 웹 화면의 접근 권한은 별개입니다.
